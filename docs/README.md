# テストケース作成ガイド

このドキュメントは、IssueやPRからシナリオベースのテストケースを作成する方法を説明します。

## 概要

Issue・PRからテストケースを作成するプロセス：

1. **Issue分析** - 業務目的と機能概要を抽出
2. **シナリオ作成** - 業務フローに基づくテストシナリオ作成
3. **PR分析** - 変更点の特定と整理
4. **影響範囲特定** - 設定、データ、環境などの因子を特定
5. **因子整理** - 因子を種類ごとに水準として整理
6. **観点整理** - 確認すべき観点を定義
7. **デシジョンテーブル作成** - 因子と観点の組み合わせをまとめる
8. **テストパターン定義** - パターン名と詳細手順を記載
9. **テスト実施** - Gherkin形式の手順で実施
10. **結果記録** - 実施結果を記録

## 例：勤怠管理システム

すべての例は**勤怠管理システム**を題材としています：

- **業務目的**: 従業員の勤怠情報を正確に記録・管理し、給与計算の基礎データを提供する
- **主要機能**: 出退勤打刻、休暇申請・承認、勤怠データ集計、レポート出力

## 作成のポイント

- **シンプルに**: 複雑さを避け、必要最小限の情報に絞る
- **一貫性**: 同じ例（勤怠管理システム）で一貫した説明
- **実践的**: 実際の開発現場で使える形式
- **追跡可能**: IssueやPRから結果までの流れを明確に
