# シナリオ概要と整理

このドキュメントでは、Issue #1（打刻機能の追加）から抽出したテストシナリオを整理します。

## Issue・PR分析からのテストシナリオ抽出

### Issueからの情報（業務目的・機能概要）

**業務目的**:
- 従業員の出退勤時刻を正確に記録
- 労働時間を適切に管理
- 給与計算の基礎データを提供

**主要機能**:
1. 出勤打刻
2. 退勤打刻

### PRからの情報（変更点）

**変更カテゴリ**:
1. データベーススキーマ追加
2. APIエンドポイント追加
3. フロントエンド画面追加
4. バリデーション追加
5. 通知機能追加

## テストシナリオの整理

### シナリオ1: 通常の出退勤打刻

**業務フロー**:
従業員が毎日の出勤・退勤時に打刻を行う標準的な業務シナリオ

**テスト対象**:
- 出勤打刻の記録
- 退勤打刻の記録
- 労働時間の自動計算
- 打刻履歴の表示

**関連変更**:
- APIエンドポイント: `/api/attendance/clock-in`, `/api/attendance/clock-out`
- フロントエンド: `ClockInOut.vue`
- データベース: `attendance` テーブル

### シナリオ2: 異常系・エッジケース

**業務フロー**:
システムの異常状態や境界条件での動作確認

**テスト対象**:
- 重複打刻の防止
- 前日退勤打刻なしの警告
- 日跨ぎ勤務の処理

**関連変更**:
- バリデーション: `attendance.js`
- 通知機能: アラート配信

## 変更点毎のテストケース整理

### 変更1: データベーススキーマ

**テストケース**:
- TC001: 出勤打刻データの登録
- TC002: 退勤打刻データの更新

### 変更2: APIエンドポイント

**テストケース**:
- TC003: 出勤打刻API実行
- TC004: 退勤打刻API実行
- TC005: 履歴取得API実行

### 変更3: フロントエンド画面

**テストケース**:
- TC006: 打刻ボタン表示と動作
- TC007: 打刻履歴の表示

### 変更4: バリデーション

**テストケース**:
- TC008: 重複打刻の防止
- TC009: 前日退勤チェック
- TC010: 出退勤時刻の妥当性検証

### 変更5: 通知機能

**テストケース**:
- TC011: 打刻完了通知
- TC012: 打刻忘れアラート

## テストの優先順位

### 優先度：高
- シナリオ1: 通常の出退勤打刻（基本機能）
- バリデーション（データ整合性）

### 優先度：中
- 通知機能

### 優先度：低
- シナリオ2: エッジケース（日跨ぎ等）
