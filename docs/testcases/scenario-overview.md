# シナリオ概要と整理

このドキュメントでは、Issue #1（打刻機能の追加）から抽出したテストシナリオを整理します。

## Issue・PR分析からのテストシナリオ抽出

### Issueからの情報（業務目的・機能概要）

**業務目的**:
- 従業員の出退勤時刻を正確に記録
- 労働時間を適切に管理
- 給与計算の基礎データを提供

**主要機能**:
1. 出勤打刻
2. 退勤打刻
3. 打刻修正

### PRからの情報（変更点）

**変更カテゴリ**:
1. データベーススキーマ追加
2. APIエンドポイント追加
3. フロントエンド画面追加
4. バリデーション追加
5. 通知機能追加

## テストシナリオの整理

### シナリオ1: 通常の出退勤打刻

**業務フロー**:
従業員が毎日の出勤・退勤時に打刻を行う標準的な業務シナリオ

**テスト対象**:
- 出勤打刻の記録
- 退勤打刻の記録
- 労働時間の自動計算
- 打刻履歴の表示

**関連変更**:
- APIエンドポイント: `/api/attendance/clock-in`, `/api/attendance/clock-out`
- フロントエンド: `ClockInOut.vue`
- データベース: `attendance` テーブル

### シナリオ2: 打刻修正申請と承認

**業務フロー**:
従業員が打刻を忘れたり誤って打刻した場合に、修正申請を行い上長が承認する

**テスト対象**:
- 打刻修正申請の作成
- 修正内容の記録
- 承認フローの動作
- 修正履歴の保持

**関連変更**:
- APIエンドポイント: `/api/attendance/correction`
- データベース: `attendance_corrections` テーブル
- 通知機能: 上長への通知

### シナリオ3: 異常系・エッジケース

**業務フロー**:
システムの異常状態や境界条件での動作確認

**テスト対象**:
- 重複打刻の防止
- 前日退勤打刻なしの警告
- GPS取得失敗時の動作
- 日跨ぎ勤務の処理

**関連変更**:
- バリデーション: `attendance.js`
- 通知機能: アラート配信

## テストの優先順位

### 優先度：高
- シナリオ1: 通常の出退勤打刻（基本機能）
- バリデーション（データ整合性）

### 優先度：中
- シナリオ2: 打刻修正申請と承認
- 通知機能

### 優先度：低
- シナリオ3: エッジケース（日跨ぎ等）
