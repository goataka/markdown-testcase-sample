# TC002: 打刻修正申請テスト

## テスト概要

**対象機能**: 打刻修正申請・承認機能  
**対応パターン**: P011, P012, P013  
**テスト目的**: 打刻修正申請の作成、承認フローの動作を確認する

## 前提条件

- テスト環境が正常に起動していること
- テストユーザー（従業員・上長）でログイン可能であること
- 通知機能が有効であること

---

## テストケース1: 打刻修正申請の作成（P011）

### 因子
- 前日状態: 退勤打刻なし（D03-2）
- 承認フロー: 1段階承認（S03-1）
- 通知: メール通知（S04-1）

### 観点
- 承認フロー: 修正申請が正常に作成され、承認者に通知される
- データ整合性: 修正履歴が正確に記録される

### 手順（Gherkin形式）

```gherkin
機能: 打刻修正申請
  従業員として
  打刻を忘れた場合に修正申請を行い
  上長の承認を得たい

  シナリオ: 退勤打刻忘れの修正申請
    前提 従業員ID "EMP001" でログインしている
    かつ 前日 "2024-01-14" の打刻記録が以下の状態である
      | 出勤時刻 | 退勤時刻 |
      | 09:00:00 | NULL |
    かつ 現在日時が "2024-01-15 10:00:00" である
    
    もし 打刻履歴画面を開く
    かつ "2024-01-14" の打刻記録を選択する
    かつ 「修正申請」ボタンをクリックする
    
    ならば 修正申請フォームが表示される
    
    もし 以下の情報を入力する
      | 項目 | 値 |
      | 修正対象 | 退勤時刻 |
      | 修正後の時刻 | 18:30:00 |
      | 修正理由 | 打刻を忘れていました。実際の退勤時刻は18:30です。 |
    かつ 「申請」ボタンをクリックする
    
    ならば 申請完了メッセージ "修正申請を送信しました" が表示される
    かつ 打刻記録のステータスが "修正申請中" になる
    かつ データベースに以下の修正申請が記録される
      | フィールド | 値 |
      | attendance_id | 対象の打刻記録ID |
      | employee_id | EMP001 |
      | correction_type | clock_out |
      | original_time | NULL |
      | corrected_time | 2024-01-14 18:30:00 |
      | reason | 打刻を忘れていました。実際の退勤時刻は18:30です。 |
      | status | pending |
    かつ 上長 "MGR001" にメール通知が送信される
```

### 期待結果

- [ ] 修正申請フォームが正しく表示される
- [ ] 申請情報が正確に入力できる
- [ ] 申請完了メッセージが表示される
- [ ] データベースに修正申請が記録される
- [ ] 上長にメール通知が送信される

## テストケース2: 修正申請の承認（P012）

### 因子
- 前日状態: 修正申請中（D03-3）
- 承認フロー: 1段階承認（S03-1）
- 通知: メール通知（S04-1）

### 観点
- 承認フロー: 承認処理が正常に動作する
- データ整合性: 承認後にデータが正確に更新される

### 手順（Gherkin形式）

```gherkin
機能: 打刻修正承認
  上長として
  部下の打刻修正申請を確認し
  承認または却下を行いたい

  シナリオ: 打刻修正申請の承認
    前提 上長ID "MGR001" でログインしている
    かつ 従業員 "EMP001" から打刻修正申請が届いている
      | 対象日 | 修正対象 | 修正後の時刻 | 理由 |
      | 2024-01-14 | 退勤時刻 | 18:30:00 | 打刻を忘れていました |
    かつ 現在日時が "2024-01-15 11:00:00" である
    
    もし 承認待ち一覧画面を開く
    
    ならば 修正申請一覧に従業員 "EMP001" の申請が表示される
    
    もし 申請詳細を開く
    
    ならば 以下の情報が表示される
      | 項目 | 値 |
      | 従業員 | 山田太郎 (EMP001) |
      | 対象日 | 2024-01-14 |
      | 修正対象 | 退勤時刻 |
      | 修正前 | 未打刻 |
      | 修正後 | 18:30:00 |
      | 修正理由 | 打刻を忘れていました。実際の退勤時刻は18:30です。 |
    
    もし 内容を確認して「承認」ボタンをクリックする
    
    ならば 承認完了メッセージ "修正申請を承認しました" が表示される
    かつ 申請ステータスが "承認済み" になる
    かつ データベースの打刻記録が以下に更新される
      | フィールド | 値 |
      | clock_out_time | 2024-01-14 18:30:00 |
      | status | approved |
    かつ 修正申請レコードが以下に更新される
      | フィールド | 値 |
      | status | approved |
      | approved_by | MGR001 |
      | approved_at | 2024-01-15 11:00:00 |
    かつ 従業員 "EMP001" にメール通知が送信される
```

### 期待結果

- [ ] 承認待ち一覧に申請が表示される
- [ ] 申請詳細が正確に表示される
- [ ] 承認処理が正常に実行される
- [ ] 打刻記録が修正内容で更新される
- [ ] 承認履歴が記録される
- [ ] 従業員に承認通知が送信される

## テストケース3: 2段階承認フロー（P013）

### 因子
- 前日状態: 退勤打刻なし（D03-2）
- 承認フロー: 2段階承認（S03-2）
- 通知: アプリ通知（S04-2）

### 観点
- 承認フロー: 2段階承認が正しく動作する
- 通知機能: 各承認者に適切に通知される

### 手順（Gherkin形式）

```gherkin
機能: 2段階打刻修正承認
  2段階承認が必要な組織で
  第1承認者、第2承認者の順に承認を行い
  最終的に修正が反映されることを確認したい

  シナリオ: 2段階承認フローでの打刻修正
    前提 従業員ID "EMP001" でログインしている
    かつ 所属部署の承認設定が "2段階承認" である
    かつ 第1承認者が "MGR001"、第2承認者が "MGR002" である
    
    # 修正申請の作成
    もし 打刻履歴から "2024-01-14" の退勤時刻修正申請を作成する
      | 修正後の時刻 | 18:30:00 |
      | 修正理由 | 打刻を忘れていました |
    
    ならば 申請が作成され、ステータスが "第1承認待ち" になる
    かつ 第1承認者 "MGR001" にアプリ通知が送信される
    
    # 第1承認者による承認
    もし 第1承認者 "MGR001" でログインする
    かつ 承認待ち一覧から申請を確認して承認する
    
    ならば 申請ステータスが "第2承認待ち" になる
    かつ 第2承認者 "MGR002" にアプリ通知が送信される
    かつ まだ打刻記録は更新されない
    
    # 第2承認者による最終承認
    もし 第2承認者 "MGR002" でログインする
    かつ 承認待ち一覧から申請を確認して承認する
    
    ならば 申請ステータスが "承認完了" になる
    かつ 打刻記録が修正内容で更新される
    かつ 従業員 "EMP001" にアプリ通知が送信される
    かつ データベースに以下の承認履歴が記録される
      | 承認段階 | 承認者 | 承認日時 |
      | 第1承認 | MGR001 | 2024-01-15 11:00:00 |
      | 第2承認 | MGR002 | 2024-01-15 11:30:00 |
```

### 期待結果

- [ ] 2段階承認フローが正しく動作する
- [ ] 各段階で適切な承認者に通知される
- [ ] 第1承認後は打刻記録が更新されない
- [ ] 第2承認後に打刻記録が更新される
- [ ] 承認履歴が正確に記録される

## テストケース4: 修正申請の却下

### 手順（Gherkin形式）

```gherkin
機能: 打刻修正却下
  上長として
  内容に問題がある修正申請を
  却下できることを確認したい

  シナリオ: 打刻修正申請の却下
    前提 上長ID "MGR001" でログインしている
    かつ 従業員 "EMP001" から打刻修正申請が届いている
    
    もし 申請詳細を確認する
    かつ 却下理由 "修正時刻が業務終了時刻と大きく異なります。再度確認してください。" を入力する
    かつ 「却下」ボタンをクリックする
    
    ならば 却下完了メッセージ "修正申請を却下しました" が表示される
    かつ 申請ステータスが "却下" になる
    かつ 打刻記録は変更されない
    かつ 従業員 "EMP001" に却下通知とコメントが送信される
```

### 期待結果

- [ ] 却下処理が正常に実行される
- [ ] 打刻記録が変更されない
- [ ] 却下理由とともに従業員に通知される
