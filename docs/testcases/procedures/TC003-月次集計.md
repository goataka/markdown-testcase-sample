# TC003: データ整合性・月次処理テスト

## テスト概要

**対象機能**: データ整合性チェック、月次集計機能  
**対応パターン**: P014, P015, P016  
**テスト目的**: データ整合性の検証と月次処理の正確性を確認する

## 前提条件

- テスト環境が正常に起動していること
- テストデータが準備されていること
- バッチ処理が実行可能であること

---

## テストケース1: 前日退勤打刻なし警告（P014）

### 因子
- 前日状態: 退勤打刻なし（D03-2）
- データベース: 通常データ（E04-2）
- 時刻: 平日（E05-1）

### 観点
- データ整合性: 前日の退勤打刻なしを検出
- エラーハンドリング: 適切な警告メッセージを表示

### 手順（Gherkin形式）

```gherkin
機能: 前日退勤打刻なし警告
  システムとして
  前日の退勤打刻がない従業員に対して
  警告を表示して打刻を促したい

  シナリオ: 前日の退勤打刻がない状態での出勤
    前提 従業員ID "EMP001" の打刻記録が以下の状態である
      | 日付 | 出勤時刻 | 退勤時刻 |
      | 2024-01-14 | 09:00:00 | NULL |
    かつ 現在日時が "2024-01-15 09:00:00" である
    
    もし 従業員ID "EMP001" でログインする
    
    ならば 警告ダイアログが表示される
      """
      前日（2024-01-14）の退勤打刻がありません。
      打刻忘れの場合は修正申請を行ってください。
      """
    かつ ダイアログに以下のボタンが表示される
      | ボタン | アクション |
      | 修正申請 | 修正申請画面へ遷移 |
      | 後で確認 | 警告を閉じる |
    
    もし 「修正申請」ボタンをクリックする
    
    ならば 打刻修正申請画面が開く
    かつ 対象日が "2024-01-14" で事前入力されている
    かつ 修正対象が "退勤時刻" で事前選択されている
```

### 期待結果

- [ ] 前日の退勤打刻なしを検出する
- [ ] 警告ダイアログが表示される
- [ ] 修正申請画面へスムーズに遷移できる
- [ ] ユーザーが適切な対応を取れる

## テストケース2: 月次勤怠集計処理（P015）

### 因子
- 前日状態: 正常終了（D03-1）
- データベース: 通常データ（E04-2）
- 時刻: 月末（E05-5）

### 観点
- データ整合性: 月次集計が正確に行われる

### 手順（Gherkin形式）

```gherkin
機能: 月次勤怠集計
  システムとして
  月末に各従業員の勤怠データを集計し
  月次レポートを作成したい

  背景:
    前提 以下の従業員が存在する
      | 従業員ID | 氏名 | 所属部署 |
      | EMP001 | 山田太郎 | 営業部 |
      | EMP002 | 佐藤花子 | 営業部 |
    かつ "2024-01-01" から "2024-01-31" の打刻記録が以下の通りである
      # 従業員EMP001の1月分打刻データ（平日20日間）
      | 従業員ID | 日付 | 出勤時刻 | 退勤時刻 | 労働時間 |
      | EMP001 | 2024-01-04 | 09:00:00 | 18:00:00 | 9.0時間 |
      | EMP001 | 2024-01-05 | 09:00:00 | 19:30:00 | 10.5時間 |
      | EMP001 | ... | ... | ... | ... |
      | EMP002 | 2024-01-04 | 09:30:00 | 18:30:00 | 9.0時間 |
      | EMP002 | ... | ... | ... | ... |

  シナリオ: 月次集計バッチ処理の実行
    前提 現在日時が "2024-02-01 00:00:00" である
    かつ 月次集計バッチが実行可能な状態である
    
    もし 月次集計バッチを実行する
      """
      batch-job run monthly-attendance-summary --month=2024-01
      """
    
    ならば バッチ処理が正常に完了する
    かつ 処理ログに "月次集計完了: 対象月=2024-01, 処理件数=2" と記録される
    かつ 月次集計テーブルに以下のデータが作成される
      | 従業員ID | 対象月 | 出勤日数 | 総労働時間 | 残業時間 | 遅刻回数 | 早退回数 |
      | EMP001 | 2024-01 | 20 | 185.0 | 25.0 | 0 | 0 |
      | EMP002 | 2024-01 | 20 | 180.0 | 20.0 | 1 | 0 |
    かつ 集計結果が正確である
      # EMP001: 平日20日、標準8時間勤務、残業計25時間
      # EMP002: 平日20日、標準8時間勤務、残業計20時間、遅刻1回
```

### 期待結果

- [ ] 月次集計バッチが正常に実行される
- [ ] 出勤日数が正確に集計される
- [ ] 総労働時間が正確に計算される
- [ ] 残業時間が正確に計算される
- [ ] 遅刻・早退回数が正確にカウントされる
- [ ] 集計結果がデータベースに保存される

```gherkin
機能: 月次勤怠レポート出力

    前提 管理者ID "ADMIN001" でログインしている
    かつ "2024-01" の月次集計が完了している
    かつ 現在日時が "2024-02-01 10:00:00" である

      EMP001,山田太郎,20,185.0,25.0,0,0

      """
```

### 期待結果

- [ ] レポート画面が正しく表示される
- [ ] 対象月・部署の選択ができる
- [ ] CSVファイルが正常にダウンロードされる

## テストケース4: 大量データでの性能確認（P016）

### 因子
- 前日状態: 正常終了（D03-1）
- データベース: 大量データ（E04-3）
- 時刻: 平日（E05-1）

### 観点
- データ整合性: 大量データでも正確に処理される
- 性能: 許容時間内に処理が完了する

### 手順（Gherkin形式）

```gherkin
機能: 大量データ処理
  システムとして
  従業員数が多い場合でも
  性能を維持して処理できることを確認したい

  シナリオ: 1000名の従業員データでの月次集計
    前提 1000名の従業員が登録されている
    かつ 各従業員に1ヶ月分の打刻記録がある（約20,000レコード）
    かつ 現在日時が "2024-02-01 00:00:00" である
    
    もし 月次集計バッチを実行する
    かつ 実行開始時刻を記録する
    
    ならば バッチ処理が正常に完了する
    かつ 処理時間が10分以内である
    かつ すべての従業員の集計が完了している
    かつ データの欠損がない
    かつ システムリソース（CPU、メモリ）が許容範囲内である
```

### 期待結果

- [ ] 大量データでも処理が完了する
- [ ] 処理時間が許容範囲内（10分以内）
- [ ] データの正確性が保たれる
- [ ] システムリソースが枯渇しない

## テストケース5: データ整合性チェック

### 手順（Gherkin形式）

```gherkin
機能: データ整合性チェック
  システムとして
  打刻データの整合性を定期的にチェックし
  異常なデータを検出したい

  シナリオ: 日次データ整合性チェックバッチ
    前提 以下の打刻データが存在する
      | 従業員ID | 日付 | 出勤時刻 | 退勤時刻 | 状態 |
      | EMP001 | 2024-01-15 | 09:00:00 | 18:00:00 | 正常 |
      | EMP002 | 2024-01-15 | 09:00:00 | NULL | 退勤なし |
      | EMP003 | 2024-01-15 | NULL | 18:00:00 | 出勤なし（異常） |
      | EMP004 | 2024-01-15 | 19:00:00 | 18:00:00 | 時刻逆転（異常） |
    かつ 現在日時が "2024-01-16 01:00:00" である
    
    もし データ整合性チェックバッチを実行する
      """
      batch-job run data-consistency-check --date=2024-01-15
      """
    
    ならば バッチ処理が完了する
    かつ 整合性チェック結果レポートが作成される
    かつ 以下の異常データが検出される
      | 従業員ID | 日付 | 異常タイプ | 詳細 |
      | EMP003 | 2024-01-15 | 出勤なし退勤あり | 出勤打刻なしで退勤打刻あり |
      | EMP004 | 2024-01-15 | 時刻逆転 | 退勤時刻が出勤時刻より前 |
    かつ 管理者にアラートメールが送信される
```

### 期待結果

- [ ] データ整合性チェックが実行される
- [ ] 異常なデータが検出される
- [ ] 検出結果がレポートに記録される
- [ ] 管理者に通知される
