# デシジョンテーブル

このドキュメントでは、因子と観点の組み合わせをデシジョンテーブルとしてまとめ、テストパターンを定義します。

## 観点の定義

| 観点ID | 観点名 | 確認内容 |
|--------|--------|----------|
| V01 | 正常動作 | 基本的な打刻操作が正常に動作するか |
| V02 | データ整合性 | データベースに正確に記録されるか |
| V03 | ユーザビリティ | ユーザーが使いやすいか |
| V04 | エラーハンドリング | エラー時に適切に処理されるか |
| V05 | 承認フロー | 修正申請の承認が正しく機能するか |

## パターン詳細

以下、各パターンの詳細手順は別ファイルで定義：

### P001: 通常出勤打刻

**因子の組み合わせ**:
- 打刻状態: 未打刻（D02-1）
- 打刻時刻: 通常勤務時間（D04-1）
- ネットワーク: 社内LAN（E03-1）

**観点**:
- 正常動作: 出勤打刻が正常に記録される
- データ整合性: データベースに正確に保存される

**詳細手順**: [TC001-打刻登録.md](procedures/TC001-打刻登録.md)

**観点**:

## テストパターンの実施順序

### フェーズ1: 基本機能（P001-P006）
優先度：高  
基本的な打刻機能とエラーハンドリングを確認

### フェーズ2: デバイス・ネットワーク（P007-P010）
優先度：中  
各種環境での動作を確認

### フェーズ3: 修正申請（P011-P013）
優先度：中  
承認フローの動作を確認

### フェーズ4: データ整合性（P014-P016）
優先度：低  
エッジケースとデータ整合性を確認
