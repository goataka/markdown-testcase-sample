# markdown-testcase-sample

テストケースをIssue、PRからMarkdownで作成する流れを検討するリポジトリです。

## 概要

このリポジトリは、IssueやPRの内容から体系的にテストケースを作成する方法を示すサンプルです。
業務目的や機能概要から、シナリオベース、因子分析、デシジョンテーブルを用いたテストケース作成プロセスを、
**勤怠管理システム**を例として一貫した形で説明しています。

### テストケース作成プロセス

1. **Issue分析** - 業務目的と機能概要を抽出
2. **シナリオ作成** - 業務フローに基づくテストシナリオ作成
3. **PR分析** - 変更点の特定と整理
4. **影響範囲特定** - 設定、データ、環境などの因子を特定
5. **因子整理** - 因子を種類ごとに水準として整理
6. **観点整理** - 確認すべき観点を定義
7. **デシジョンテーブル作成** - 因子と観点の組み合わせをまとめる
8. **テストパターン定義** - パターン名と詳細手順を記載
9. **テスト実施** - Gherkin形式の手順で実施
10. **結果記録** - 実施結果を記録

## ドキュメント構成

```
├── samples/                     # サンプルIssue・PR
│   ├── issue-sample.md          # Issue例：打刻機能の追加
│   └── pr-sample.md             # PR例：打刻機能の実装
├── testcases/                   # テストケース作成
│   ├── scenario-overview.md     # シナリオ抽出と整理
│   ├── factor-analysis.md       # 因子分析（設定・データ・環境）
│   ├── decision-table.md        # デシジョンテーブル
│   └── procedures/              # テスト手順（Gherkin形式・日本語）
│       ├── TC001-打刻登録.md
│       └── TC003-月次集計.md
└── results/                     # テスト結果記録
    └── 2024-01-15-TC001-結果.md
```

## 使い方

1. **[サンプルIssue](samples/issue-sample.md)** で業務目的・機能概要を確認
2. **[サンプルPR](samples/pr-sample.md)** で変更点を確認
3. **[シナリオ概要](testcases/scenario-overview.md)** でテストシナリオの抽出方法を学ぶ
4. **[因子分析](testcases/factor-analysis.md)** で影響範囲と因子の特定方法を学ぶ
5. **[デシジョンテーブル](testcases/decision-table.md)** でテストパターンの組み合わせを確認
6. **[テスト手順](testcases/procedures/)** でGherkin形式の手順を確認
7. **[テスト結果](results/)** で結果記録の形式を確認

## 例：勤怠管理システム

すべての例は**勤怠管理システム**を題材としています：

- **既存機能**: 出退勤打刻、打刻履歴表示、労働時間計算
- **追加機能**: 打刻修正機能（直接修正、修正履歴管理）
- **業務目的**: 打刻忘れや誤打刻を従業員が直接修正でき、上長は修正履歴を確認できる仕組みを導入し、勤怠データの正確性を向上させる

## 特徴

- **シンプル**: 複雑さを避け、理解しやすい構成
- **一貫性**: 勤怠管理システムの例で一貫した説明
- **実践的**: 実際のプロジェクトで使える形式
- **追跡可能**: IssueからPR、テストケース、結果まで追跡可能
- **Gherkin形式**: テスト手順は日本語のGherkin形式で記述
